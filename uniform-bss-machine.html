Section 3

Uniform BSS machine

Keming Meng · 15-455 Project Writeup

Now that we have laid the form of the model for finite inputs, we now give a uniform model, that can take any finite input.

First, we need to change our input, state, and output spaces.

A natural way to define the input space, since it can take values of any finite size, is to define it as

\[\mathbb R^{*}\]

which is equal to the union of \(\mathbb R^{n}\) for \(n\ge0\). Likewise, the output space should take values in \(\mathbb{R}^{*}\).

The real question is how we should model the state space. If we think back to the Turing Machine, the state space is essentially modeled using an infinite tape. Following this as inspiration, we define the state space to be \(\mathbb R^{\infty}\), which is the set of sequences

\[(\ldots,r_{-1},r_0\,.\,r_1,\ldots)\]

such that only finitely many of the \(r_i\) are nonzero (note that between \(r_0\) and \(r_1\), there is a period, which helps us keep track of positions on the ”tape”. In particular, we will use the period to index positions on the tape, with the position right before the period as the 0th position).

Now that we have appropriately defined the various spaces of our machine, we can now fully define the model.

Definition 8. A BSS machine is a finite directed graph with 5 different node types. As seen before, the graph has a unique input node, which is equipped with a map sending the input \(x\) to \((\ldots,n,x,\ldots)\) in the state space, where \(n\) is simply \(n\) ones. The computation nodes are almost the same as the finite dimensional case, with the only difference being that the function associated with the computation node is \(g:\mathbb{R}^{\infty}\to\mathbb{R}^{\infty}\), which is defined via \(g(\ldots,x_{-1},x_0,x_1,\ldots)=(\ldots,x_{-1},x_0\,.\,\hat g(x_1,\ldots,x_m),x_{m+1},\ldots)\), where \(g:\mathbb{R}^{m}\to\mathbb{R}^{m}\) is a rational function in each coordinate for some fixed \(m\). Likewise, the branch node in this case is a node associated with a polynomial \(h:\mathbb{R}^{\infty}\to\mathbb{R}\) defined by \(h(\ldots,x_{-1},x_0,x_1,\ldots)=\hat h(x_1,\ldots,x_m)\), where \(m\) is some fixed natural, and \(\hat h:\mathbb{R}^m\to\mathbb{R}\) is a polynomial. Then, we add new nodes, those being the left and right shift nodes, with the associated left and right shift functions which move the values in our state space to the right or to the left, depending on which shift it is. Finally, we have an output node, which has associated with it an output map from the state space to \(\mathbb{R}^{*}\), which is defined by

\[O(\ldots,x_{-1},x_0\,.\,x_1,\ldots)=0\]

if \(x_0\) = 0, and otherwise is equal to \((x_1,\ldots,x_\ell)\), where \(\ell\ge0\) is the first index where \(x_{-\ell}\) = 0.

Finally, we note that even with this model of computation much of the work will depend on the finite-dimensional model. To see why, note that if we investigate a given halting time \(T\), then we can reduce the model down to a finite-dimensional one. In particular, when looking at a given halting time \(T\), note that we can then use at most \(T\) shifts. It then suffices to only look at a finite number of coordinates in our state space, as we will never reach further coordinates in the halting time \(T\). This effectively reduces much of our work to the finite-dimensional case.

In particular, when reducing to a finite-dimensional scenario, we are often interested in understanding

\[\Omega_T^n\]

for a given BSS machine \(M\) which is the first \(n\) coordinates of the inputs such that \(M\) halts in time \(T\).

With a uniform model of computation now at hand, we can begin to define the complexity classes \(P\) and \(NP\).
